2. Installation & Drop-In

The ascended file is a drop-in replacement for your original. Follow these steps:

  1. Extract the ZIP archive
  2. Back up your existing agent.py
  3. Rename cmpsbl_agent.py to agent.py
  4. Place the renamed file in the same location as your original
  5. All capabilities are pre-activated — no configuration changes needed
Why rename? The ascended file is named differently to prevent accidental overwrites during extraction. Once renamed, it functions identically to the original with additional Layer 2 capabilities.

5. Layer 2 Architecture

The CMPSBL® Layer 2 is a patented behavioral wrapper that surrounds your code without modifying it. Think of it like a protective shell that adds capabilities:

  • Layer 1 (L1) — Your original source code, completely untouched
  • Layer 2 (L2) — Behavioral wrapper providing governance, security, and activated capabilities

The ascended file contains both layers as a single distribution. The L2 wrapper intercepts function calls, adds behavioral policies, and enables the activated capabilities — all without modifying a single byte of your original source code.

Deactivating Specific Capabilities

If you need to deactivate a specific capability, locate the capability block in the ascended file and set its active flag to false:

9. Troubleshooting

  • Ensure you renamed cmpsbl_agent.py to agent.py
  • Check that the file is in the same directory as the original
  • Verify your build system recognizes the file extension

  • If your bundler complains, ensure it supports the target language syntax

Performance concerns?

10. Advanced Configuration

Debug Mode — See the Layers Working

By default, Layer 2 runs silently — your code behaves identically to before, just with governance, resilience, and observability quietly active underneath. To see the machinery for yourself, enable Debug Mode. It prints the active layer roster on the first call and surfaces one honest line per real BEACON signal. No synthetic events, no fake triggers — only what actually fires.

Two ways to enable:

# Option 1 — environment variable (recommended for CLI / scripts)
CMPSBL_DEBUG=1 node agent.py

# Option 2 — per-call flag (recommended for selective debugging)
cmpsbl_execute("my_capability", { _cmpsbl_debug: true, ...input });

Sample output:

[CMPSBL] Layers active: CIRCUIT-BREAKER, TIMEOUT, RETRY, ENVELOPE, TRACE, DEGRADATION, BEACON
[CMPSBL] First call: my_capability
[CMPSBL] my_capability ok (12ms)
[CMPSBL] my_capability FAIL (304ms) via CMPSBL_TIMEOUT

Debug output is gated behind a single boolean check — when disabled (the default), there is zero stdout, zero performance impact, and the export is byte-identical to running without it.

Custom Capability Ordering

Capabilities execute in CJPI-descending order by default. To change execution order, modify the _capabilityOrder array in the ascended file.

Mana Enhancement

This export was not Mana-enhanced. To add SDK-based capabilities, re-run the pipeline and select "Enhance" during Step 2.
